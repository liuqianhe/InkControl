# 功能开发示例

新增功能以一个明确行为为单位，例如新增可选锁屏信息，先定义 `lock.example` 的 ID、选项、依赖、作用进程、HOT／REBOOT 和实验标记。

1. 在 `core/FeatureCatalog` 添加静态定义。默认开关自动为关闭。选项必须有限且可校验，不能塞入可执行文本。
2. 在 `features/lock` 的对应处理器读取不可变快照；关闭时立即走原厂分支。需要接管系统状态时先保存实际原值和写入值，停用采用条件恢复。
3. 外部能力通过平台适配器提供。页面仍只调用 `ApplicationServices.change`；不要在页面、Provider 调用参数或 FeatureCatalog 中执行系统操作。
4. 复杂分支放进独立处理器和数据模型。Hook 回调只采集事件并转交，绘图只接收模型，不去订阅媒体、查询 Root 或操作另一项功能的内部对象。
5. 给参数、依赖、默认关闭、父级停止、重开和恢复写有意义的电脑测试；系统行为在目标设备保留实测证据。实验功能必须标注实验状态。

不需要再添加一个配置文件、独立 Provider、插件注册框架或后台 Android 服务。构建时从 Java 功能目录生成 `features.tsv` 与 `defaults.txt`，后端自动得到同一份白名单和默认配置；不要手动维护第二份。

热更新处理器完成初始化后调用 `RuntimeConfig.markReady()`，执行失败用 `RuntimeConfig.fail()` 上报，不能仅写日志却回报成功。新增启动期行为必须有本次启动回执和停用恢复路径。旧实验快照不得在新功能开发中改写。
